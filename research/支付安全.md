## 支付安全

```
├─ 身份认证
│
├─ 通信安全
│   ├─ HTTPS
│   ├─ TLS
│   └─ 证书
│
├─ 数据安全
│   ├─ AES/SM4
│   ├─ RSA/SM2
│   └─ 签名验签
│
├─ 业务安全
│   ├─ 防重放（不要让垃圾请求进来; 时间戳：5min后的攻击，随机数：5min内的攻击，签名：避免时间戳随机数被篡改）
│   ├─ 防刷单
│   ├─ 风控
│   └─ 限流
│
└─ 资金安全
    ├─ 幂等（垃圾请求进来了也不能出事; 业务结果都只能生效一次，UPDATE pay_order WHERE status=WAIT_PAY）
    ├─ 补单（微信侧支付成功，业务侧没处理时补单）
    ├─ 对账
    └─ 账务系统
```

## 重复下单问题

```
商品页
 ↓
确认页
 ↓
生成 orderToken（关键）
 ↓
提交订单
 ↓
消费 orderToken
 ↓
创建订单
 ↓
业务规则校验
 ↓
成功
```

## 支付流程

```
订单 O1001
    │
    ▼
创建支付单 P1001
    │
    ▼
微信支付
    │
    ▼
微信流水 WX888888
    │
    ▼
微信回调
    │
    ▼
UPDATE pay_order
WHERE status=WAIT_PAY（支付回调幂等）
    │
    ├── 成功(1行)
    │      │
    │      ├── 更新订单
    │      ├── 记账
    │      └── 发货
    │
    └── 失败(0行)
           │
           └── 已处理过
```

## 总结

```
重复下单 → orderToken
重复支付/回调 → 支付幂等
漏单/状态不一致 → 补单
最终资金一致 → 对账
```

```
L1 查询级
↓
查看数据
→ 登录态 + 权限校验（菜单/按钮/api） + 数据权限（企业隔离 + 角色隔离）

L2 交易级
↓
修改业务状态
→ 状态机 + 幂等（状态机控制“能不能这样改”; 幂等控制“重复操作只生效一次”）+ 操作日志

L3 资金级
↓
修改资金状态
→ 支付幂等 + 金额校验 + 资金流水 + 补单 + 对账
```
