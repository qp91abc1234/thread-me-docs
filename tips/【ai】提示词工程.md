## 提示词协议

`Spec + Rules + Context + Tests` 构成了与 AI 大模型进行高质量协作的工程协议。

### 四个核心模块

| 模块 | 英文 | 开发场景 | 通用场景 | 核心本质 |
| --- | --- | --- | --- | --- |
| Spec | Specification | 定义需求 | 要AI完成的任务 | 目标定义 |
| Rules | Rules | 代码规范 + 输出规范 | 行为边界 + 输出规范 | 遵循准则 |
| Context | Context | 项目上下文 | 当AI做决策所需的背景信息 | 决策依据 |
| Tests | Tests | lint / tsc / 单测 | 判断“结果对不对”的标准 | 验收标准 |

## cursor 提示词工程

- **AGENTS.md**：项目介绍、背景、架构说明（始终加载，用于给 Agent 建立项目认知）。
  - 建议保持精简：由于每次都会全量进入 `context`，内容越多，占用越大。
  - 建议策略：只保留“让 Agent 理解项目必须知道的最小信息”；详细模块说明拆分到对应子目录的 `AGENTS.md`，按需加载。
- **Rules**：必须遵守的约束和规范（`alwaysApply` 或 `globs`，强制生效）。
- **Skills**：可复用的操作能力（语义触发，按需加载）。
  - 组件 Skill 的独特性在于：它处在一个**"Agent 能理解但不会主动关联"的盲区**，而 Skill 的语义触发机制恰好填补了这个盲区
- **任务级提示词**：提示词协议
