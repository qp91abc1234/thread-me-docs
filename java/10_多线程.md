## 线程

Runnable 无返回值

```java
new Thread(() -> {
    System.out.println("Hello");
}).start();
```

Callable 有返回值

```java
// 1. 创建 Callable 任务
Callable<String> callable = () -> {
    Thread.sleep(2000);
    return "任务执行结果";
};

// 2. 用 FutureTask 包装 Callable（FutureTask 实现了 Runnable）
FutureTask<String> futureTask = new FutureTask<>(callable);

// 3. 通过 Thread 执行（因为 FutureTask 是 Runnable 的子类）
Thread thread = new Thread(futureTask);
thread.start();

// 4. 获取执行结果（会阻塞直到任务完成）
String result = futureTask.get();
System.out.println("结果：" + result);
```

### sleep

sleep() 永远让调用所在的线程休眠，休眠不会释放锁

```java
// 线程 A 执行这行代码 → 线程 A 休眠
Thread.sleep(1000);

// 线程 B 执行这行代码 → 线程 B 休眠（即使前面写了 targetThread）
targetThread.sleep(1000);  // 依然是执行这行代码的线程休眠！
```

## 线程池

```java
int cpuCores = Runtime.getRuntime().availableProcessors();

ExecutorService executor =
    new ThreadPoolExecutor(
        int corePoolSize,           // 1. 核心线程数
        int maximumPoolSize,        // 2. 最大线程数
        long keepAliveTime,         // 3. 空闲存活时间
        TimeUnit unit,              // 4. 时间单位
        BlockingQueue<Runnable> workQueue, // 5. 工作队列
        ThreadFactory threadFactory, // 6. 线程工厂
        RejectedExecutionHandler handler // 7. 拒绝策略
    )

executor.submit(() -> {
    System.out.println("执行任务");
});

// 存在返回值，使用时不区分 runnable 和 callable

Future<Integer> future =
    executor.submit(() -> {
        return 100;
    });

Integer result =
    future.get();
```

### 参数解析

- corePoolSize
  - 核心线程数：常驻线程数，即使空闲也不会被销毁
  - 配置经验
    - CPU密集型（计算为主）：CPU核数 + 1
    - IO密集型（数据库、RPC调用）：CPU核数 \* 2（可更大）
- maximumPoolSize
  - 最大线程数：线程池允许创建的最大线程数
    - 当队列满了，才会创建新线程直到达到此值
  - 配置经验：一般为 corePoolSize \* 2 或根据压测
- keepAliveTime + unit
  - 空闲存活时间
- workQueue
  - 工作队列
  - submit() 提交的任务会先进入 workQueue（工作队列）排队，然后才被工作线程取出并执行
- threadFactory
  - 线程工厂
  - 作用：给线程起名字，方便排查问题
- handler
  - 拒绝策略
  - 当线程池和队列都满了，新任务如何处理

### 完整配置

```java
int cpuCores = Runtime.getRuntime().availableProcessors();

new ThreadPoolExecutor(
    cpuCores + 1,                    // corePoolSize
    cpuCores * 2 + 1,                // maximumPoolSize
    60L,                             // keepAliveTime
    TimeUnit.SECONDS,
    new LinkedBlockingQueue<>(2000), // 有界队列，防止OOM
    new ThreadFactoryBuilder()
        .setNameFormat("biz-pool-%d")
        .build(),
    new ThreadPoolExecutor.CallerRunsPolicy()
);
```

### 任务执行流程

```java
提交任务 (submit)
    ↓
① 核心线程是否已满？
    ├─ 否 → 核心线程执行
    └─ 是 → 进入②
            ↓
② 工作队列是否已满？
    ├─ 否 → 进入队列等待
    └─ 是 → 进入③
            ↓
③ 线程总数是否达到最大线程数？
    ├─ 否 → 创建新线程执行
    └─ 是 → 触发 CallerRunsPolicy！ // 当 CallerRunsPolicy 触发后，提交任务的线程（比如主线程）会立即、同步、阻塞地执行该任务，直到任务执行完毕，才会继续执行后面的代码
            ↓
        【主线程（提交者）亲自执行该任务】
```

## 概念

- 公平锁 vs 非公平锁 - 排队获取 vs 谁抢到谁得
- 可重入锁 - 同一个线程可以多次获取同一把锁（synchronized 和 ReentrantLock 和 ReentrantReadWriteLock都支持）

### 悲观锁 & 乐观锁

悲观锁是强制锁：锁，操作，释放锁
乐观锁是逻辑锁：适合读多写少，自旋成功率高，CAS（比较并交换）是典型实现

```java
// CAS 自增的伪代码（你的理解完美对应）
do {
    // 1. 【读取值】获取当前值 V
    int oldValue = atomicInt.get();

    // 2. 【计算新值】基于旧值算出新值
    int newValue = oldValue + 1;

    // 3. 【比较相同，计算新值】核心操作！
    //    如果内存中的值还是 oldValue（没人改过），就更新为 newValue -> 成功跳出
    //    如果内存中的值已经不是 oldValue（被人改了），则操作失败 -> 重试
} while (!atomicInt.compareAndSet(oldValue, newValue));
```

## synchronized 同步锁

同步锁：谁拥有了锁对象，谁就可以执行锁修饰的代码块

### 使用

修饰实例方法：锁的是当前实例对象 this

```java
public synchronized void method() { // 锁 this
    // 临界区
}
```

修饰静态方法：锁的是该类的 Class 对象

```java
public static synchronized void staticMethod() { // 锁 Class
    // 临界区
}
```

修饰代码块

```java
// 锁 this 或指定实例对象
synchronized (this) { ... }

// 锁 Class 对象
synchronized (Demo.class) { ... }

// 锁一个专用的成员变量（推荐）
private final Object lock = new Object();
synchronized (lock) { ... }
```

### 四大特性

- 原子性：被锁住的代码块在执行时是“不可分割”的，不会被线程调度机制中断。
- 可见性：进入 synchronized 锁时，线程会使本地缓存中的共享变量副本失效，强制从主内存重新获取最新值；释放锁时，会强制将工作内存中的修改刷新回主内存。
- 可重入性：同一个线程可以多次获得同一把锁（比如一个 synchronized 方法调用另一个 synchronized 方法），不会死锁，JVM 会自动记录加锁次数。
- 非公平性：默认是非公平锁。当锁释放时，新来的线程和等待队列中的线程会竞争，可能导致等待久的线程“饿死”，但优势是吞吐量更高（这也是 JVM 默认选它的原因）。

## ReentrantLock 可重入锁

核心铁律：必须手动加锁和释放锁，且释放锁必须放在 finally 块中，确保即使异常也能解锁。

```java
ReentrantLock lock = new ReentrantLock();

// 标准写法
lock.lock(); // 加锁（不可中断）
try {
    // 临界区代码
} finally {
    lock.unlock(); // 必须释放
}
```

### 四大特性

可中断锁：通过 lockInterruptibly() 等待获取锁时。如果线程在等待锁时被外部中断，可以响应中断并抛出异常，避免死等

```java
lock.lockInterruptibly(); // 等待锁时可被 interrupt() 打断
```

超时机制：通过 tryLock(long time, TimeUnit unit) 尝试获取锁。如果超时未获取到，线程可以放弃等待，去做其他事情（比如重试或记录日志）

```java
if (lock.tryLock(1, TimeUnit.SECONDS)) { // 等待1秒
    try {
        // 获取成功
    } finally {
        lock.unlock();
    }
} else {
    // 获取失败，执行备选方案
}
```

公平/非公平锁：构造时传入 true 即为公平锁（先到先得）。但默认是非公平的，因为公平锁会降低吞吐量（需要维护等待队列），除非业务上严格要求顺序

```java
ReentrantLock lock = new ReentrantLock(true);
```

可重入：同一线程可以重复获取同一把锁（计数器累加）

### Condition

```java
ReentrantLock lock = new ReentrantLock();
Condition notEmpty = lock.newCondition(); // 负责"非空"条件

// 线程1：等待非空
lock.lock();
try {
    while (队列为空) {
        notEmpty.await(); // 释放锁并等待
        // 被唤醒并重新获取锁后，【从这里继续执行】！
        //    （即从 await() 的下一行代码开始）
    }
    // 消费数据
} finally { lock.unlock(); }

// 线程2：生产后唤醒
lock.lock();
try {
    // 生产数据
    notEmpty.signal(); // 精准唤醒等待"非空"的线程
} finally { lock.unlock(); }
```

## ReentrantReadWriteLock 读写锁

读锁是共享（计数）的，写锁是独占的。有读锁，写锁进不来；有写锁，读锁和写锁都进不来。

当前锁状态： │ 【空闲】 │ 【持有读锁】 │ 【持有写锁】
─────────────────┼─────────────┼───────────────┼───────────────
新线程来拿【读锁】│ ✅ 立刻拿到 │ ✅ 立刻拿到 │ ❌ 阻塞等待
新线程来拿【写锁】│ ✅ 立刻拿到 │ ❌ 阻塞等待 │ ❌ 阻塞等待

```java
ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
Lock readLock = rwLock.readLock();   // 获取读锁
Lock writeLock = rwLock.writeLock(); // 获取写锁

// 读操作：允许多个线程同时进入
public String getData() {
    readLock.lock();
    try {
        // 读取共享数据（不修改）
    } finally {
        readLock.unlock();
    }
}

// 写操作：独占，其他读写线程全部阻塞
public void setData(String data) {
    writeLock.lock();
    try {
        // 修改共享数据
    } finally {
        writeLock.unlock();
    }
}
```

### 四大特性

重入性：支持锁重入，但读锁和写锁的重入规则不同：

- 写锁重入：同一个线程可以重复获取写锁（重入次数增加）。
- 读锁重入：同一个线程可以重复获取读锁（重入次数增加）。
- 降级重入：持有写锁时获取读锁是允许的（降级）。
- 升级重入：持有读锁时获取写锁是不允许的（死锁）。

```java
// 锁降级的标准写法（常见于缓存更新）
writeLock.lock();
try {
    // 1. 更新数据...
    readLock.lock(); // 2. 在写锁中获取读锁
} finally {
    writeLock.unlock(); // 3. 释放写锁，降级为读锁
}
try {
    // 4. 使用降级后的读锁读取数据...
} finally {
    readLock.unlock();
}
```

其余三项与可重入锁一致
